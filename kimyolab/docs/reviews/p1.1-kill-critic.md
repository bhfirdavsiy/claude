## 10 ta savol

### 1. Student-facing modeldan correct answerni to‘g‘ridan olish mumkinmi? — **PASS**
- **Evidence:**
  - `LearningHubModel.assessment.items` = `toPromptView` (`id`, `stem`, `options`). U prompt qatlamidan quriladi, bu qatlamda kalit fizik jihatdan yo‘q.
  - `validatePromptPack` sızdırılgan maydonni rad etadi.
  - Guard `ASSESSMENT_KEY_IN_PRESENTATION` features/bootstrap’da `correctOptionId`, key tiplari va evaluator ishlatilishini taqiqlaydi.
- **Test:** `phase12-assessment-bank` (`doesNotMatch correctOptionId`), `p1-assessment-integrity` (projection, leak rejection), `p1-content-regression` (122 ta LU).
- **Remaining limitation:** `ContentClient` submission’dan keyin key pack’ni modul ichidagi keshda ushlab turishi mumkin (global’da emas). Devtools debugger bilan uni ko‘rsa bo‘ladi (Q3 ga qarang).

### 2. DOM’da key chiqadimi? — **PASS**
- **Evidence:**
  - Render faqat prompt view’dan chiziladi.
  - Natija `data-result="correct|incorrect"` bilan belgilanadi. To‘g‘ri variant va explanation ko‘rsatilmaydi.
- **Test:** E2E `assessment-runtime.spec`:
  - `page.content()` da `correctOptionId`, `scoringRule` yoki `data-correct` yo‘q;
  - ilova qo‘shgan `window` global’larida key materiali yo‘q (pristine iframe bilan solishtiriladi);
  - sahifa yuklanishida `assessment/keys.json` so‘ralmaydi.
- **Remaining limitation:** submission’dan keyin key pack network orqali yuklanadi. Bu javoblar qulflangandan keyin sodir bo‘ladi, lekin DevTools Network’da ko‘rinadi.

### 3. Public content packda key mavjud bo‘lsa, limitation ochiq yozilganmi? — **RISK (hujjatlashtirilgan)**
- **Evidence:**
  - Kalit static deployment’da `assessment/keys.json` ichida.
  - Standalone HTML ham uni o‘z ichiga oladi: `dist-standalone/KimyoLab_standalone.html` da `correctOptionId` bor, `contentJsonFiles: 39`.
  - ADR-P1-002 §2 “UI-separated, exam-grade emas” deb aniq yozadi.
- **Test:** `p1-assessment-integrity` testi pack’ning alohida key faylini va authored bank’ning pack’da yo‘qligini tekshiradi.
- **Remaining limitation:** exam-grade secrecy uchun server-side evaluation kerak. Port (`AssessmentContentSource`) tayyor, lekin amalga oshirilmagan.

### 4. Reflection mastery evidence bo‘lib qolganmi? — **PASS**
- **Evidence:** `submitReinforcement` faqat `REINFORCEMENT_COMPLETED` beradi. Evidence yo‘li faqat `recordEvaluatedAssessment` va practice orqali o‘tadi.
- **Test:** “reflection → REINFORCEMENT_COMPLETED only: 0 assessment evidence, 0 attempts…”. Bu test legacy `objective_quiz` payload’ni ham qamraydi.
- **Remaining limitation:** yo‘q.

### 5. Wrong assessment ham evidence sifatida qayd etiladimi? — **PASS**
- **Evidence:** har item × concept bo‘yicha `correct:false`, `score:0`, `correctness:'incorrect'` evidence yoziladi.
- **Test:** “wrong answers are evidence too”, E2E’da `some(e=>e.correct===false)`.
- **Remaining limitation:** yo‘q.

### 6. Assessment retry oldingi attemptni o‘zgartiradimi? — **PASS**
- **Evidence:**
  - Yangi sessiya = yangi attempt id.
  - Store `add` qiladi (overwrite yo‘q).
  - Topshirilgan sessiyani qayta topshirish `ASSESSMENT_ALREADY_SUBMITTED`.
- **Test:** “assessment retry creates a new attempt…” — birinchi attempt va evidence deep-equal saqlanadi. E2E’da ikkinchi submit ikkinchi attempt yaratadi, birinchisi o‘zgarmaydi.
- **Remaining limitation:** yo‘q.

### 7. Activity ikki engine’ga resolve bo‘lishi mumkinmi? — **PASS**
- **Evidence:**
  - `compileExecutionPlans` quyidagilarni rad etadi: `ROUTE_CONFLICT`, `type` va config zidligi (`CONFIG_ENGINE_MISMATCH`), capability va engine nomuvofiqligi.
  - `resolveExecutionPlan` dublikat plan’da xato beradi.
  - Session va router plan’ning `engine`/`activityId` ni tekshiradi.
- **Test:** `p1-canonical-routing` (conflict, mismatch, router mismatch).
- **Remaining limitation:** yo‘q.

### 8. Runtime noma’lum routingda guess qiladimi? — **PASS**
- **Evidence:** plan pack’dan o‘qiladi, derive qilinmaydi. Noma’lum runtime, engine yoki capability hamda yo‘q plan’da xato beriladi (fail-closed). `configFamily` runtime’dan olib tashlangan, guard `LEGACY_ROUTING_KEY` uning qaytishini taqiqlaydi.
- **Test:** “runtime lookup never guesses…”, “the browser path executes exactly the compiled plan… tampered plan fails closed”.
- **Remaining limitation:** reliz qilinmagan `practice.simulation.10.4` da route yo‘q va u `disabled` deb hisoblanadi (reliz qilinsa build yiqiladi).

### 9. Assessment integration user-visible masteryni tasodifan yoqdimi? — **PASS**
- **Evidence:**
  - `USER_VISIBLE_MASTERY=false`: `displayStatus` `mastered`/`needs_review` ni `assessment_complete` (“Test topshirildi”) deb ko‘rsatadi.
  - `CycleSnapshot.status` ham `DisplayStatus`.
  - Feedback’da mastery maydonlari yo‘q.
- **Test:** “C1 stays disabled…”, E2E “progress page does not show a mastery status”.
- **Remaining limitation:** mastery store’da hisoblanadi (P1.2 uchun). Uni ko‘rsatish P1.2 qarori.

### 10. Existing 122 LU kontentiga regressiya kirdimi? — **PASS**
- **Evidence:**
  - 122 ta LU hub’i quriladi.
  - Reliz qilingan 118 ta activity o‘z plan’i bilan yuklanadi va engine’ini quradi.
  - Kontent versiyasi o‘zgarmadi (`2026.09.1`). Pack’ga `execution-plans.json`, `assessment/prompts.json` va `assessment/keys.json` qo‘shildi. Authored bank olib tashlandi.
- **Test:** `p1-content-regression` (ikkala test), P0 va P1.0 suite’lari, parity.
- **Remaining limitation:** pack tarkibi o‘zgargani uchun pack checksum o‘zgardi, versiya esa o‘sha qoldi. Oldingi build keshiga ega klient yangi manifest’ni checksum orqali oladi (P0 integrity).
